Servlet Assignment standalone WAR

Same Java code as the embedded project, deployed a completely different way: packaged as servlet-assignment.war, dropped into a real Tomcat's webapps/, mapped by WEB-INF/web.xml.

Look at the address bar. Everything now sits under /servlet-assignment — that prefix is the context path, and it comes from the WAR's filename.

Q1 — Calculator (validated by a filter)

Break it to watch the filter reject the request before the servlet runs: a=abc · op=% · divide by zero · missing b

Q2 — Character count

Seeing the JSON from a browser

Append &format=json to any URL: calculate?a=6&b=3&op=*&format=json

Compare the two deployments

If the embedded project is also running on port 8080, the same request is localhost:8080/calculate?a=6&b=3&op=* there and localhost:8081/servlet-assignment/calculate?a=6&b=3&op=* here. Identical responses, identical Java, two entirely different ways of getting a server.
